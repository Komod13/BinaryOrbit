# BinaryOrbit · 双星轨道

自托管的情侣足迹地图。把自己和女朋友吃过的饭店、去过的景点记在高德地图上，另一个页面看走过的城市。数据存在本机的 SQLite 文件里，只在家里局域网用，没有账号，也不上传到任何服务器。

## 功能

### 标记页（`/map`）

**就近记录。** 地图中心有个准星，把地图拖到店门口，点「搜索附近」，按 500m / 1km / 3km（默认 1km）查这一带的餐厅和景点。结果按距离排序，已记过的会标「已记录」。点一条就自动带上名称、地址、坐标、分类和城市，只要补日期。

**关键词补录。** 顶部搜索框默认在地图中心所在城市里搜，右侧可以切成全国。输入一个字就开始给建议，↑↓ 选择、Enter 打开、Esc 关掉；建议里同时包含你已记过的地点和高德的检索结果。

**手动记点。** 在「搜索附近」抽屉底部有个「在地图上手动记一笔」，这是唯一的手动录入入口。保存前会检查 50m 内有没有同名地点，有的话让你选是合到已有地点，还是仍然新建。

**记录内容。** 餐厅记用餐日期、1–5 星评分（可选）、人均价位档和备注；景点记游玩日期和备注。价位档默认低 `<60`、中 `60–150`、高 `>150` 元/人，阈值可以在 `.env` 里改。同一家店再次记录不会建重复地点，只会追加一次到访。

**地图观感。** 餐厅和景点是两类标记，密集时聚合成带数字的气泡。缩放级别 ≥13 时常显店名，更小的时候只在鼠标悬停或选中时显示。底图用 CSS 滤镜压成安静的米色；底图文字注记默认按 zoom 分级（低 zoom 显示城市名、高 zoom 隐藏），可用 `.env` 的 `MAP_LABELS` 调整。

**详情与删除。** 点标记打开详情：总到访次数、最近一次日期、平均评分，以及每条到访的日期、星级、价位和备注。删除需要二次确认，按钮会变成红底「确认删除？」，3 秒内再点一次才生效。删掉某个地点的最后一条到访，这个地点也会一起被删掉。

顶部的筛选按钮是「全部 / 餐厅 / 景点」，各带数量，选择会记住。

### 足迹页（`/cities`）

全国地级市边界常驻显示，都是真实的地理轮廓，不是方块。有记录或手动点亮过的城市会上色，常显城市名和「餐厅 N · 景点 M」。

- **点亮城市：** 点任意未上色的城市，选「点亮」就计入城市总数，不需要真的在里面记过地点。
- **回到地图：** 点已点亮的城市，选「在地图上查看」会跳回标记页，视野框住该城的标记并高亮。
- **航线：** 按首次到访日期把各城市中心依次连成虚线。

直辖市按省合并成一个城市（上海就是上海，不拆成 16 个区）。台湾没有可用的边界数据，画不出来，也不能点亮。港澳正常。

边界数据来自 DataV.GeoAtlas，第一次进这个页面要联网逐省下载，全量约 3.7MB，之后完全离线。

### 统计浮窗

右上角常驻三个数字：餐厅、景点、城市。两个页面都有。桌面端展开成卡片，窄屏收成一个「N 处足迹」的小徽标，点开是同一张卡片。折叠状态会记住。

### 端适配

一套响应式，断点 860px。宽屏是右侧栏加常驻统计卡，窄屏换成底部抽屉加统计徽标，手机上打开「搜索附近」时地图会缩到抽屉上方，准星和半径圈不会被挡住。

## 快速开始（Windows）

**前置：** Node 24 或更高版本，以及 Git。先 `node -v` 确认，低于 24 会在启动时直接退出（后端依赖 `node:sqlite`，22.x 需要实验性参数）。

1. 拉代码：

   ```bat
   git clone https://github.com/Komod13/LoveMap.git
   cd LoveMap
   git pull
   ```

2. 装依赖（只需第一次，依赖被 gitignore，不会随仓库下来）：

   ```bat
   npm install
   ```

3. 准备配置。把 `.env.example` 复制成 `.env`，填三个高德 key：

   ```bat
   copy .env.example .env
   ```

   三个 key 在[高德开放平台](https://console.amap.com/)申请，需要个人实名认证：

   | 变量 | 用途 | 申请时选的服务平台 |
   |---|---|---|
   | `AMAP_JS_KEY` | 前端渲染地图 | Web端(JS API) |
   | `AMAP_SECURITY_CODE` | 同一应用的「安全密钥 jscode」，只在服务端用 | — |
   | `AMAP_WEB_KEY` | 后端检索 POI、逆地理、行政区划 | Web服务 |

   注意两件事：Web端 key 的**域名白名单要留空**，否则用局域网 IP 打开会报 `INVALID_USER_DOMAIN`；`.env` 里的注释要单独成行，不要写在值后面。

4. 双击 `启动.bat`。

   它会检查 Node 版本、`node_modules` 和 `.env`，并在 `web/dist` 缺失或**比 `web/src` 旧**时自动重新构建前端（`git pull` 不会带上前端产物，不重建就会一直跑旧包），然后启动服务。控制台会打印本机地址、局域网地址、二维码、当前前端 bundle 名和构建时间，并自动打开浏览器。

   局域网地址是自动挑的：`192.168` 网段优先，会跳过 Clash / WSL / VMware / Docker 这类虚拟网卡（它们经常排在内置网卡前面）。挑错了就用二维码下面「其他网卡」里列出的地址，或者直接在 `.env` 里写 `LAN_IP=192.168.88.209`。

手机要和电脑连同一个 WiFi，扫码即可。第一次连接时 Windows 防火墙会弹窗，选「专用网络」，否则手机连不上。服务监听 `8787` 端口，浏览器直接访问 `http://<电脑IP>:8787`。

## 开发

改代码用 `开发.bat`：后端以 `--watch` 跑在 8787，同时起 Vite 开发服务器，访问 `http://localhost:5173`，接口和地图代理会转发到后端。生产构建产物在 `web/dist`（gitignore），改动前端后要么手动 `npm run build`，要么直接重启 `启动.bat`（它会自己判断源码比 dist 新就重建）。`index.html` 现在带 `cache-control: no-cache`，`/assets/*`（带 hash）是一年长缓存，所以改完刷新就能拿到新包，不会卡在旧页面。

| 命令 | 作用 |
|---|---|
| `npm start` | 启动生产服务（需要先构建 `web/dist`） |
| `npm run build` | 构建前端到 `web/dist` |
| `npm run dev:server` / `dev:web` | 单独起后端 watch / Vite |
| `npm test` | 后端集成测试（`node --test`，高德接口全部 mock） |
| `npm run typecheck` | `vue-tsc --noEmit`（含 `.vue` 里的 script） |

### 手机上排查卡顿

在地址后面加 `?debug=1`（例如 `http://<电脑IP>:8787/map?debug=1`），左下角会出现一个自检面板，实时显示：

- **帧率**：当前 fps、这期间最低 fps、卡顿（单帧 ≥200ms）次数
- **主线程**：50ms 定时器的最大漂移（iOS 不支持 `longtask`，用这个代替），以及长任务统计
- **地图**：高德每秒重绘多少帧、用的是 WebGL 画布还是栅格瓦片、当前 zoom
- **标记**：已画出的标记数 / 地点总数、上一次重建耗时
- **环境**：dpr、视口尺寸、构建时间戳、当前 URL 参数

进页面 8 秒后自动上报一次，之后每 20 秒一次（报的是这段时间里的最差值）；也可以拖动几下后点面板上的「上报到电脑控制台」。上报内容会直接打印在 `启动.bat` 那个窗口里，形如：

```
  [diag] 收到浏览器端诊断
         reason           手动上报
         build            2025-11-08 23:12
         query            ?debug=1&dpr=1
         fps              60
         minFps           3
         worstFrameMs     384
         frozenFrames     6
         loopLagMs        340
         mapFramesPerSec  12
         mapFramesMax     46
         renderer         webgl
         markers          0
         places           10
         zoom             12
         dpr              2
         viewport         1373x816
         touchPoints      5
         slowResources    ["820ms jsapi-data2.amap.com/tile/..."]
```

怎么读：

- `minFps` 低 + `frozenFrames` 多 + `loopLagMs` 也大 → 主线程被占着（高德渲染 JS 或我们的代码）；
- `minFps` 低但 `loopLagMs` 很小 → 主线程没事，卡在 GPU / 合成器；
- `mapFramesPerSec` 只有几帧、`slowResources` 里有高德瓦片 → 在等网络；
- `places` 有值但 `markers` 是 0 → 不是数据没了，是筛选或未重建，把 `filter` 切回「全部」。

### 底图注记与卡顿

iPad 实测结论：高德 2.0 WebGL 的**矢量文字注记**会把主线程占住 300ms+，与 POI 图标、建筑、像素填充率、网络、标记层都无关。注记在高德那边是「一整层」（`AMap.*.LabelsLayer`）或按要素类型（`road` / `point`）整体开关，**没有「只留一部分」的接口**，能做的是按 zoom 分级。

所以注记策略做成了 `.env` 配置（改完重启生效，手机/平板与电脑共用一套）：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `MAP_LABELS` | `auto` | `auto`：低于 `MAP_LABEL_MAX_ZOOM` 才显示（省名 / 城市名，数量少不卡），再往里隐藏；`on`：始终显示（iPad 上会卡）；`off`：始终隐藏 |
| `MAP_LABEL_MAX_ZOOM` | `12` | `auto` 模式的注记上限 zoom，3–18 |

调试时可以用 URL 参数临时覆盖（优先级高于 `.env`）：`?labels=on|off|auto`、`?labelzoom=13`，配合 `?debug=1` 的 `mapOptions` 字段能看到实际生效值。

> 桌面端高德走栅格瓦片，注记是烘在瓦片图片里的，这个开关实际上只影响 iPad / 手机这类 WebGL 渲染。

实现上没有重建地图：建图后找 `CLASS_NAME` 含 `Label` 的图层调 `setVisible()`，并在 `zoomend` 时同步，所以「低 zoom 显示、高 zoom 隐藏」是实时的。

对照实测（2026-11-08，Chrome iOS / iPadOS 18，dpr 2，zoom 15–18，地点 0 条）：

| 配置 | minFps | frozenFrames | loopLagMs |
|---|---|---|---|
| 注记开 | 3–6 | 3–12 | 295–353 |
| 注记关 | 40–58 | 0 | 10–70 |
| 注记关 + 只留底色道路 | 56–58 | 0 | 9–26 |

> 排查过程中试过「按 dpr 降分辨率」「换 DOM/栅格渲染」：前者无改善；后者（改 `AMap.Browser.isWebGL`）在 iPad 上白屏，因为 `Support.baseRender` 在 JSAPI 初始化时已定死。这两条路都已回滚，代码里没有留下开关。

另外启动横幅里会打一行 `前端 index-xxxxx.js · 构建时间`：手机上报的 `build` 应该和它一致，不一致就说明手机上跑的是旧前端（换个页面/强制刷新）。

## 配置项

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `8787` | 监听端口 |
| `AMAP_JS_KEY` | — | 前端地图 key，经 `/api/config` 下发 |
| `AMAP_SECURITY_CODE` | — | 安全密钥，由后端代理注入，不出现在浏览器 |
| `AMAP_WEB_KEY` | — | Web 服务 key，仅后端使用 |
| `PRICE_TIER_LOW` | `60` | 低档上限（元/人） |
| `PRICE_TIER_HIGH` | `150` | 高档下限（元/人） |
| `LAN_IP` | 自动 | 手机访问用的局域网地址。默认按网段和网卡名挑（192.168 优先，跳过 Clash / WSL / VMware 等虚拟网卡）；挑不对时手动写一个，如 `192.168.88.209` |
| `MAP_LABELS` | `auto` | 底图注记策略：`auto` 按 zoom 分级（默认）、`on` 始终显示、`off` 始终隐藏 |
| `MAP_LABEL_MAX_ZOOM` | `12` | `auto` 模式下注记显示的 zoom 上限（3–18） |

三个高德 key 缺任意一个，启动时会打印中文提示并退出，不会带着不完整的配置跑起来。

## 数据与备份

所有数据在一个 SQLite 文件里：`data/orbit.db`（同目录还有 WAL 模式的 `-wal`、`-shm`）。首次启动自动建表。备份就是把整个 `data/` 目录复制走，恢复就是放回去。`data/` 和 `.env` 都在 gitignore 里，不会进仓库。

服务监听 `0.0.0.0:8787`，没有认证，也不做端口转发，请只在自己家里的局域网使用。

## 已知边界

- 不做手机定位：定位需要 HTTPS，这一期没有，所以「附近」是以地图中心为锚点的周边检索。
- 地点和到访只能新增和删除，不能编辑。
- 没有照片、分享页、时间轴，也没有历史数据导入。
- 城市页只负责看和点亮，不会反过来改地图页的筛选。

二期计划（编辑、照片墙、年度总结、HTTPS 与定位、数据导出等）记在设计文档里。
